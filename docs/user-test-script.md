# 使用者測試腳本（spec §11.6 商業驗證）

**對象：** 10–20 位近期（3 個月內）有大阪／京都自由行計畫的台灣旅客。排除旅遊業從業者。
**時長：** 30 分鐘，線上或面對面，錄影需另取得同意。

## 實驗前預註冊（填好再開始）

| 指標 | 定義 | 門檻（實驗前填寫） |
|---|---|---|
| 完成率 | 從開始到看到比較結果的比例 | |
| 3 分鐘內建立任務 | 計時 | |
| 人工修正次數 | 使用者修改自動解析／估算段數的次數 | |
| 找到可買的省錢方案 | 推薦方案為 Pass 且使用者認為可行 | |
| 點擊官方購買連結 | 行為事件 | |
| 付費意向 | 點「我願意付 NT$149」 | |
| 信任 | 1–5 分：「我相信這個價格是對的」 | |

## 流程

1. **暖身（3 分）**：上次自由行怎麼決定買不買 Pass？花多少時間？
2. **任務一（8 分）**：用自己的真實行程，從首頁開始建立比較。不提示。觀察：卡在哪、是否看懂「估算」與「已驗證」的差別。
3. **任務二（5 分）**：打開「來源與方法」，請對方說出推薦方案的依據與資料日期。
4. **任務三（6 分）**：選擇「請懶人包協助預填」，看核准卡後決定要不要核准。問：哪一行讓你放心／不放心？
5. **任務四（3 分）**：載入「資料過期」情境，請對方解釋為什麼不能購買。
6. **收尾（5 分）**：願不願意付費？付給哪一段（比較、預填、多站點追蹤）？想要的下一個懶人包？

## 紀錄

每位受訪者一列：完成時間、修正次數、推薦結果、是否點官方連結、付費意向、信任分數、最大的疑問（原話）。
不把「說願意付費」當成真實付款；真實付款需另做合規的預購測試。
